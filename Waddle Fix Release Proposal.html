Milestones and “done when” tests

Tap a milestone to expand it. The tests are proposals for you to adjust before work starts.

1Stop users being logged outTrial task

Work: trace the refresh flow in Dio interceptors and the NestJS refresh endpoint, then fix the cause named in your review. Handle simultaneous requests failing at once, refresh-token renewal and clean sign-out when a session really has expired.

Done when: a test account stays signed in across access-token expiry and across app restarts days apart, on a real iPhone and Android phone. An expired refresh token leads to a clean login, with no loop and no surprise logout.

2Firebase AnalyticsApp

Work: add Firebase Analytics with automatic screen views (via a GetX route observer) and a short list of key events with consistent snake_case names, agreed with you first.

Done when: every agreed screen and event appears in Firebase DebugView from both the iOS and Android builds.

3Admin: edit events and places, add website fieldAPI · DB · Admin

Work: editing for all events and parent-added places, a new nullable website column via a Prisma migration, URL validation, and the field shown in the app where places appear.

Done when: an admin edits an event and a place, saves a website, and the change shows in the live app. The migration runs safely on a copy of production data.

4Admin: export users to CSVAPI · Admin

Work: an admin-only endpoint and a download button, with properly escaped fields and streaming for larger lists.

Done when: the file opens correctly in Excel and Google Sheets, and its row count matches the database. Non-admins are refused.

5Configuration clean-up and route accessAPI · Ops

Work: move keys and settings to environment variables, add .env.example, and add guards to the server routes you name. Any secret already committed should be rotated.

Done when: no secrets remain in the repo, the app runs from environment variables on EC2, and unauthorised calls to the listed routes return 401 or 403.

6Device QA and store releaseRelease

Work: a regression pass on real devices with your test accounts, then production builds for both stores with a short release note.

Done when: the agreed checklist passes and both builds are submitted together for store review.
